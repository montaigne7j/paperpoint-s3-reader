# V1.8.1 input responsiveness diagnostics

V1.8.1 is a small Paper S3 reader responsiveness update.  It does not change the
TTF memory policy, frame-cache memory gates, or EPD waveform profile.

## Goals

- Make touch / button events visible in release serial logs by promoting key
  `TOUCH` and reader input diagnostics to `INF` level.
- Keep exactly one pending page-turn command while the visible renderer or
  background frame-cache job is busy.
- Count reader input events so field logs can distinguish touch detection,
  queued input, busy ignores, pending ignores, and executed input.
- Emit warnings when display idle waits, render locks, or pending page turns take
  longer than expected.

## New counters

Reader logs now include:

```text
Reader input counters: event=... source=...
  touchDetected=...
  inputQueued=...
  inputIgnoredBusy=...
  inputIgnoredPending=...
  inputExecuted=...
```

## Busy handling

When a page-turn event arrives while render/cache is busy, the reader keeps one
pending command:

```text
Reader input detected: source=render-busy ...
Page turn queued: dir=next source=render-busy ...
```

If another page-turn arrives before the pending command executes, it is counted
as `inputIgnoredPending` rather than silently disappearing.

## Warnings

Long waits now appear at `INF` level:

```text
Reader busy warning: source=render-busy busyFor=... threshold=500ms
Reader pending input warning: source=reader-loop queuedFor=... threshold=1000ms
Reader display busy warning: source=cache-hit wait=... threshold=500ms
```

These logs are intended for diagnosing occasional “button/touch did not respond”
reports without enabling full debug logging.
